# 原生控制与验收

桥接和 MCP 服务统一版本为 0.10.3。必须成套构建、安装和运行；新增参数在发送前核桥接最低版本，防止旧桥接忽略参数后执行不同动作。完整入口见[工具目录](tool-reference.md)。

## 正常游戏边界

建设使用当前存档的资金、解锁、内容资格、可购土地和原生校验。`force=true`、独立不可见资产、成就授予、编辑器资源写入和任意反射调用不开放。既有 `force` 参数只接受 false，这改变了旧版允许绕过部分解锁的行为。Anarchy 的辅助显示与建造规则分开；启用错误放行、重复唯一建筑或扩展高程时，正常施工拒绝继续。

道路、建筑、扩建、搬迁、分区、地形与复合资产沿各自原生工具定义、预览、校验和应用流程操作。公共服务升级按原生 `m_ForbidMultiple` 及建筑类型判断是否允许重复，固定扩建不凭名称推断重复资格。目录中的容量、效率、员工、水电、维护和效果须与实际安装数量一起解释。

## 预览与真实结果

`cs2_place_prop`、`cs2_place_interchange`、`cs2_build_road_layout`、`cs2_remove_road_layout` 默认 `dryRun=true`；这些入口生成原生预览，返回能否应用、原生费用与错误后清除预览，不收费。`cs2_place_building` 可显式传 `dryRun=true` 使用相同的原生预览与清除流程；未传时保留原有实际施工语义，非法布尔值在排队前拒绝。

独立道路布局的曲线 `y` 是相对布局原点的坐标，不能当作相对地面的高程。桥接转换到世界坐标，按每段道路的原生 UI 范围检查控制点、沿线不超过 4 米的取样和共享节点均值；固定端点保留世界高度，结构高程来自实际地面差值。连接道路的默认自由端与吸附端也检查实际高程，不能省略参数后将地下专用网络放到地面。

原生预览返回错误位置、临时实体及实际生成的道路贝塞尔几何；道路几何最多 256 条并报告是否完整，错误位置分别有 32/64 条上限。临时身份在预览清除后失效，只用于诊断，不得拿来继续施工。

部分较早接口的 `dryRun` 只计算位置或参数，包括建筑搬迁、建筑升级、路边/岸线放置、连接道路、地形笔刷、采掘区域编辑和道路服务标志解析。它们的说明明确写出限制；不能把这类结果当作碰撞、收费、完整路径或运营验收。实际执行仍经过原生校验。

`cs2_road_path` 预先验证全部段的参数及要求的端点连续性，再逐段施工，没有整体事务或回滚。失败响应保留成功前缀、失败位置和未知结果标记。预览时前段没有施工，后段只能吸附当前已有现场。

原生应用接受后，回读实际实体、曲线、生成车道、端口、资金、已安装升级和处理结果。工具返回 accepted/requested 不证明交通通畅、车辆出车、乘客到达或服务容量已经满足。地形、水流和经营统计可能要等模拟推进后更新；原始计数、速度和费用单位按入口说明保留。

## 实体、加载与失败恢复

实体需要完整 `index` / `version`。同一存档重载也可能重新分配编号；保存不等于重载，`cs2_game_state.loadedSaveGuid` 记录当前实际加载身份。切城、加载中或重新加载后必须重新读取实体与场址，不重放旧施工参数。

MCP 传输错误返回 `mayHaveApplied` 和 `safeToRetry`。网络中断、超时、无效成功 JSON、服务端异常，以及地形多笔触部分应用都不能当作“尚未施工”。只有明确尚未入队的短暂 busy 响应允许重试；道路路径整批错误始终禁止自动重放。先检查现场，再决定新的动作。

施工路由在入队前读取 Windows 原生进程内存与提交预算：保留至少 2 GiB 或提交上限的 15%，且进程私有内存低于提交上限的 65%。计数器未知也拒绝施工，ping 仍提供诊断；保存和正常退出不受该门槛阻断。预算来自 `GlobalMemoryStatusEx` 的进程可用提交额度，不直接冒充系统 `CommitTotal`。结构化 `resource_budget` 包含拒绝阶段、计数器/余量/进程比例原因及门槛，余量不足不等于泄漏或必须重启；禁止自动重放。这是保守资源保护，不能证明内存泄漏已修复。

## 可选模组

通过已经加载的程序集和既有系统访问固定接口，不加载指定 DLL、不修改其他模组源码、不接受远程类型/方法/字段名。此版本按 Anarchy 1.8、Traffic 0.2.13、Traffic Light Manager 1.7.6、Road Builder 0.7、Network Tools 1.5.8、Node Controller 1.5.2 和 Better Bulldozer 1.3.19 的契约实现；未来接口或 UI 范围变化须重新验证。

Network Tools 与 Traffic 同时只保留一个原生会话。prepare 返回 operationId；读取 `cs2_mod_operation` 到预览就绪，再带相同 operationId 明确 apply 或 cancel。会话过期、被其他工具打断、重载或失败后先回读；Traffic 连接是原生 toggle，重放可能反转结果。结束时恢复原工具及临时校验选项。Move It 撤销历史及 Node Controller 原始几何写入不开放。

Network Tools 的节点及 shape 操作在原生 ToolOutput 之前提交；节点 apply 前只恢复本次明确选择，避免重建并清除已经校验的预览。重载时仍清除贡献分支的操作与旧实体状态。

Traffic Light Manager 数值范围从原生 ModManager 登记的实际加载资产旁 UI 文件读取；文件/格式未知时拒绝数值写入。模板、部分配时变更及完整放行掩码先验证后调用原模组回调。Road Builder 只生成独立模板。Better Bulldozer 永久记录按所属建筑内预制体匹配，预览列出全部受影响装饰，经营、升级、道路和交通子元素受保护。

Skyve 诊断只读取标准用户数据目录或显式 `CS2_GAME_USER_DATA` 指定目录中的有限缓存/日志，敏感内容脱敏；缓存时间、缺失审查、读取失败与运行中程序集分别报告。没有订阅、登录、配组或缓存写入口。

## 构建与验证

默认构建不部署 DLL；游戏正常退出、备份旧版本后，才使用 `-p:DeployToLocalMods=true`。`-p:SkipDeploy=true` 仍可显式阻止部署。

```powershell
dotnet build CS2MCP.Bridge/CS2MCP.Bridge.csproj -p:SkipDeploy=true -p:GamePath="<game-install-directory>"
cd mcp-server
npm ci
npm test
```

无游戏依赖的 C# 诊断：

```powershell
dotnet run --project tests/Bridge.Diagnostics/Bridge.Diagnostics.csproj
```

诊断链接实际 HTTP、数值校验、内存预算及信号范围源码；游戏类型替身仅用于 HTTP ping，不模拟游戏行为。TypeScript 测试通过真实 MCP stdio 握手及独立 loopback 模拟桥接验证参数、版本拒绝、分页、预览和失败语义。测试均使用合成数据，不携带玩家存档或验收现场。

截图和保存预览仅读取 Unity 已渲染帧，不主动重复渲染相机。默认保存包含缩略图，需要可用的前台帧；后台保存须显式传 `includePreview=false`，通过原生空预览请求序列化城市数据，不等待帧结束、不恢复前台。前台预览使用原生要求的 RGBA32 格式；任务异常被明确读取，纹理在异步结束后释放。保存响应只确认原生异步管线结束，调用方仍须核文件新鲜、完整性和备份。

## 后台模拟与图形设置

`cs2_graphics_settings` 读取原生垂直同步及基础渲染上限；`cs2_set_graphics_settings` 接受布尔 `vSync` 与 10–240 的整数 `maxFps`。这是本接口支持范围，不宣称是原生 UI 滑块，也不自动识别前后台；指定上限要求垂直同步关闭。只持久化明确指定的基础上限，加载完成后恢复，暂停加载也生效。0.10.3新增显式 `launchMode=background/foreground`（30/90基础帧）；游戏启动时可设置 `CS2MCP_LAUNCH_MODE`。未指定模式保留玩家设置，模式与 `maxFps` 冲突或与启用垂直同步冲突时全部拒绝；不根据焦点猜模式。加载期间只维护运行时帧率/同步参数，不反复应用整套画质设置。上限、实测渲染帧率、显卡驱动插帧与有效模拟速度分别解释；不改变驱动设置，不承诺某个帧率。

`cs2_set_simulation(backgroundSimulation=true)` 明确启用本次加载的后台运行，通过原生时间 UI 补偿失焦暂停，保留菜单、保存及错误暂停屏障。正常倍速仅 0/1/2/4，未知原生时钟入口拒绝控制，切城或重载后关闭后台控制，旧定时停止目标同时清除。定时结束使用同一暂停入口，避免后台控制再次恢复运行。

`cs2_milestone_popup` 读取待确认的原生里程碑通知；`dismiss=true` 使用正常达到里程碑后的继续动作，不解锁、授予成就、添加资金或清除错误/保存屏障。确认是写操作，使用 POST，失败结果不允许盲重试。

本地开发版本已验证后台无缩略图保存、重载限帧与独立布局的高程正反例；贡献版本另行通过构建、MCP 契约及 C# 诊断，未部署进游戏。这些检查不能替代完整异步会话、搬迁、地形、多种资产布局及模组版本组合的实机验收；失焦补偿和里程碑通知未触发的分支也不算实机通过。内存预算保护不证明持续内存增长已经解决。

HTTP 客户端保持无凭据 loopback HTTP origin、禁止重定向。本贡献新增的写入与预览入口在调用处显式使用 POST；基准已有入口保留原有方法。传输层不按路径自动改写方法或转发 token。通用 POST/Host/Origin/token 防护由独立安全贡献负责。服务器仍严格验证请求目标、版本、Content-Length 与 Transfer-Encoding，保留 UTF-8 请求体和空格/字面加号区分。

## 0.10.2 查询与施工修正

`cs2_rebuild_service_building` 仅重建已有的损毁服务主体或服务附属。目标必须仍存在、正常解锁，并已由灾害救援完成清障；内部子建筑不独立重建。默认 `dryRun=true` 生成并清除原生重建预览，实际应用仍受原生碰撞和收费约束。回执不证明设施恢复运营，须回读损毁、附属、端口及资金。

建筑详情分别报告清障进度、殡葬及消防运行组件。设施容量使用原生 `UpgradeUtils.CombineStats` 合并当前生效升级，停用升级不计入容量。殡葬详情包含实际车队、派车、停驻、路径及效率下的车辆容量；车队最多列 128 项，原始处理速率不换算为未经证明的月处理量。

`cs2_utilities` 读取原生水电统计、贸易和外部端口所有者上的容量及流量，`cs2_outside_connections` 列出全部原生交通与公用外联。结果明确污水外送是付费处置，保留原生单位及无界容量哨兵，不把端口总和当作全网吞吐。超过完整读取上限时返回错误，不把截断结果标为完整。公交线路详情另列实际寻路元素追溯出的道路和读取完整性；道路图返回原生街道名称及 Aggregate 身份。

`cs2_resource_diagnostics` 按请求读取进程提交/物理内存、Unity/Mono/图形驱动计数、临时实体、焦点及两次读取间基础渲染帧率。首次读取没有帧率样本；零计数可能表示平台不提供。接口不启用 Profiler、不强制 GC、不卸载资源，诊断不能证明泄漏原因或已经修复。

道路高程接受有限数值，由桥接按当前道路及已解锁地下变体的原生范围判断，不再统一裁成 -30..60 米。美化升级保留已有公交、自行车、过街和结构标志；应用结束后比较实际升级标志，不一致时返回 `mayHaveApplied=true` 并禁止自动重放。玩家切换工具会结束桥接请求，并保留玩家当前工具；已进入应用阶段的中断按结果未知处理。

边段服务入口不接受 `Crosswalk`，须通过 `nodeController.crosswalk` 指定节点及接邻道路。桥接先初始化真实端部再改过街模式，回执只读稳定标量；Node Controller 状态明确列出省略的几何及不可用属性，避免未初始化的几何 getter 将已执行动作误报为失败。替代步行路径仍须独立验收。

0.10.2 的 MCP 契约测试使用合成数据和独立模拟桥接；完整 C# 构建验证游戏程序集兼容性。公共贡献构建不部署，也不能代替新增重建、路网和模组组合的游戏内验收。


## 0.10.3 生命周期及轨道查询

HTTP关闭与入队共用同步门；关闭后不再交付新请求，只完成尚未送进处理器的队列。SDK仅在完整的 `bridge_stopped` 阶段证明下接受“未开始”；缺失/矛盾证明、处理器开始后的500、保存或工具中断仍需回读，不能盲重试。关闭不会抢占已交付原生异步操作的结果所有权。

截图与保存预览在等待帧末之前检查可用游戏帧。保存协程中断时，原生Task若仍借用纹理，保留到Task完成后在Unity主线程释放；临时渲染纹理和失败的缩图独占纹理沿各自异常边界释放。原生系统拥有的高度图、水图和组件容器不能当作本方法私有分配释放。控制点只有在尚未进入调度的准备失败时立即释放，已调度作业的释放依赖其JobHandle。

`cs2_relocate_transit_stop` 默认完整原生预览，仅允许现有正常路边公交/电车站沿当前道路同侧搬迁。目标实体、道路身份、位置和 `expectedLoadedSaveGuid` 全部验证；显式 `dryRun=false` 才应用并正常收费，保旧站实体及线路站序。真实路径、车辆停靠和步行接入须另验，应用不明时禁止重放。

`cs2_list_transit_lines(includePathTrace=true)` 逐实际PathElement列车道、Edge/Node及Owner链，指定0基 `pathSegment` 并按 `pathOffset/pathLimit` 分页；重复经过保留顺序。缺失Owner、层数截止或分页都不冒充完整路径，寻路结果和实际运营分别核验。车型候选/选择使用原生SelectVehiclesSection的正常内容、客货、能源和尺寸资格，普通列车primary栏为车厢、secondary栏为机车；两栏是独立集合。旧车保持原模型，新的选择集合不证明既有编组已经改变。

产业产消、资源图、专门产业构建/边界、工业资源税以及市辖区编辑由独立贡献负责，本贡献没有这些增量入口。基准已有工业综合税率、市辖区创建/政策和道路/车型入口保留；通用改名拒绝市辖区，通用放置拒绝需要专门经营建筑附着的产业占位体。商业/办公资源税与住宅学历税仍保持各自正常校验。职责边界见[贡献范围](contribution-scope.md)。
